## Responsibility

Executes the §0.1 routing checkpoint without becoming a second engineering authority. Canonical applicability remains owned by the doctrine taxonomy and the active agent semantic classification; the runtime only resolves and gates the declared route.

## Protocol

1. Before covered work on each prompt, classify the current stage and every applicable surface and condition. If canonical signal IDs are not already known, invoke this skill once without arguments to receive the generated catalog.
2. For a full route, invoke this skill with exactly one `stage:*` signal plus every applicable `surface:*` and `condition:*` signal, separated by spaces or commas.
3. If applicability is genuinely unknown, invoke with `diagnose`, perform only minimal read-only diagnosis, then declare the full route. Use `none` only when the prompt requires no Doctrine-covered work; any subsequent tool use invalidates `none`.
4. The runtime resolves the declaration through the generated canonical route map and reports the required Doctrine skills and supporting references. Invoke and read all of them before other covered tool use.
5. Re-invoke this skill before the next covered action whenever stage, surface, or condition changes. Persistent `Edit`, `Write`, and `NotebookEdit` calls require a current route containing `condition:mutation`.
6. Do not use `none` or `diagnose` to bypass applicable rules. A no-argument invocation is bootstrap only and does not establish a route.
